## 3. 메인컴 적용 절차

실거래 시스템이므로 **장 마감 후 또는 장 시작 전**에 적용하고, 순서대로 진행한다.

```bash
cd <MQK-v3 저장소 경로>

# 0) 사전 점검 — 로컬 변경·원격 차이 확인 (수정 없음)
git status -sb
git fetch origin main
git log --oneline HEAD..origin/main        # 위 10개 커밋이 보여야 함
git diff HEAD origin/main --stat           # 로컬이 GitHub와 크게 다르면 여기서 중단하고 검토

# 1) 런타임 상태 파일 백업 (git에 추적되는 data/*.json 보호)
mkdir -p ~/mqk_backup_$(date +%F) && cp -r data logs ~/mqk_backup_$(date +%F)/ 2>/dev/null

# 2) 반영 (로컬 미커밋 변경이 없을 때)
git pull --ff-only origin main

# 3) 테스트 (환경에 pytest가 있다면)
python -m pytest tests -q

# 4) MQK 프로세스 재시작 — 프롬프트는 프로세스 시작 시 한 번만 읽는다
pm2 restart all          # 또는 mqk-v3-* 프로세스만 선택 재시작
pm2 list
```

주의:
- `data/last_regime_v4.json` 등 `data/*.json`은 git에 추적되는 런타임 파일이다. `git pull` 시 로컬 변경과 충돌하면 위 백업을 확인한 뒤 처리한다.
- 메인컴 저장소가 GitHub와 다르다면(예: 별도 로컬 커밋) `--ff-only`가 실패한다. 이 경우 강제로 덮어쓰지 말고 차이를 먼저 검토한다.
- 환경변수 `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`(또는 `TELEGRAM_NOTIFY_CHAT_IDS`)가 설정되어 있어야 레짐 실패 경고가 전송된다.

- **confidence 임계값 값**: 현재 기본 75(65~95). 코드가 BUY를 숫자로 막지는 않으므로 프롬프트 지시에만 의존한다. `analyze_confidence.py` 결과(구간별 20건 이상)를 보고 값과 코드 강제 여부를 정한다.
- **레짐 갱신 실패 시 매매**: 11:03·13:03·15:10에 실패하면 당일 앞선 레짐으로 매매가 계속된다. 매매를 멈추려면 별도 플래그 추가가 필요하다.
- **`close.md` sell_type**(`PRICE_FAIL`, `TIME_EXIT`, `GAP_RISK_EXIT`): 코드에서 처리하는 곳을 찾지 못했다. 실제 청산에 쓰이는지 확인이 필요하다.
- **뉴스 제거의 성과 영향**: 모의 운영·백테스트로 검증되지 않았다.
- **셋업 이름**: `THEME_CATALYST`, `THEME_FADE`는 코드 호환을 위해 이름을 유지하고 정의만 뉴스 없는 기준으로 바꿨다.
